About Me
I'm a software engineering student and developer focused on becoming a strong backend engineer. I'm interested in how software works beneath the surface: how services communicate, how data is modelled and protected, how systems scale, and how architectural decisions affect reliability and performance.
I'm learning to approach development as an engineering discipline—not simply as the process of making an application work. That means understanding the problem first, choosing appropriate data structures and algorithms, modelling data carefully, designing clear interfaces, testing assumptions, debugging systematically, and being able to explain the trade-offs behind my decisions.

- Backend engineering: APIs, business logic, authentication, validation, concurrency, testing, and service design.

Engineering Mindset
I want to be the kind of engineer who can do more than produce code quickly. I'm working toward being able to:
- Translate ambiguous requirements into clear, testable specifications.
- Design data models, APIs, and service boundaries before rushing into implementation.
- Explain why a solution works, where it may fail, and what its trade-offs are.
- Read unfamiliar code, investigate bugs, use logs and tests, and debug from evidence.
- Think about security, correctness, performance, reliability, and maintainability—not just the happy path.
- Use AI-assisted development as a tool while retaining ownership of the design, code, and final result.
- Document decisions and communicate technical ideas clearly.
